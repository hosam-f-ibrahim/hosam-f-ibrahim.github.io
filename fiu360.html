The problem

A financial intelligence unit is the national body that receives reports from banks and other reporting entities, analyzes them and passes intelligence to law enforcement. Building the system it runs on means solving several hard problems at once.

  • Reports arrive from many reporting entities, in formats the unit itself defines, and each one has to be validated before anyone can rely on it.
  • The value of a report is in its connections: the people, entities, accounts and transactions it shares with everything the unit already holds.
  • Analysts need data from outside the report, from financial, national, international and open sources, and gathering it by hand is slow and error-prone.
  • The whole cycle has to meet FATF and UN standards and stay configurable as each unit's requirements change.

The decision that shapes everything: one linked core

FIU360 does not store reports as documents to be read later. Every report is broken into the objects it carries, with the links between them, and integrated into one core database. Screening, enrichment, search, analytics, visualization and case management all work on that same picture.

That is why a new report about a person or account the unit already knows arrives as intelligence connected to everything already held, not as one more file in a queue. Around the core, each stage of the cycle is a module aligned to one functional area, so the capabilities work together while each stays configurable, and the platform comes in three editions, so a unit can start with the modules it needs and upgrade later.

Report intake: correctness first, then throughput

Collection runs through a configurable XML engine with 300+ parameters that define exactly what each report type must contain: CTR, STR, EFT and AIF. Every submitted report is validated against its XML schema, staged in the internal database and checked by a business-rule engine before any of its data reaches analysts.

Only then is it broken into every object it carries, from reports, persons, entities, accounts, transactions and identifications to many more, with the relationships between them, and integrated as linked, investigation-ready intelligence. The pipeline sustains 100K+ records an hour end to end, measured on a commodity server.

From linked data to intelligence

Incoming data is screened against sanctions lists, with selective matching to cut false positives, alerts, case confirmation, whitelisting of repeated false positives and escalation of confirmed cases. A process designer lets administrators attach a workflow to any report or case type; when a report arrives, FIU360 assigns its first step to the right staff member and tracks the time spent on each task.

Analysts search and update persons, accounts, entities, transactions, phones and addresses through AI-driven search that builds links, profiles and associations between them, and use LLM-powered analytics for both operational and strategic intelligence. Investigations run in case management built on four layers: access control, security settings, case types and the AML/CFT case module. Scanned and office documents attach to the intelligence database with their text extracted for search.

FATF statistics take one click, BI dashboards are drag-and-drop with drill-down and can be delivered to decision-makers' inboxes, and dissemination to law enforcement is automated. Throughout, role-based access control, detailed auditing, encryption and logging of every user action protect the data, and IT administrators can maintain the system without accessing sensitive data. Across the cycle, the platform cut analyst effort by 90%.

Two add-ons: FIU360 Connect and enhanced visualization

I also architected two add-ons that extend FIU360, and other existing FIU and AML systems, without changing their code base. The enrichment add-on was first built for other FIU systems and later connected to FIU360; I continued its design and development as FIU360 Connect.

The moment a report arrives, or whenever an analyst asks, FIU360 Connect reaches out to financial, national, international and open sources, then cleanses, deduplicates and normalizes what comes back through parallel, multithreaded ETL pipelines, so analysts see the reported data and its enrichment side by side. Reliability was designed in rather than added later: validation, error handling and retry logic, data secured in transit with TLS, third-party API providers held to SLAs, and production monitoring in Application Insights. Connect delivers 99% data accuracy, cut acquisition latency by 99% and reduced enrichment failures by more than 90%.

Enhanced visualization

Standard visualization tools show only some of the objects in a database. The enhanced visualization add-on renders every object and relationship stored in the system and maps them across external databases through dynamic connectors, giving analysts one connected view. Pre-aggregating relationship data in SQL Server views and stored procedures cut its load times by 50%.

Both sides of the exchange

Reports start with reporting entities, so I also delivered AML PRO, which their compliance officers use to bring in data from spreadsheets and organizational databases, correct inconsistencies before submission and submit compliant XML reports from day one.
